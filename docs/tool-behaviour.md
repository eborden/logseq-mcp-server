# Tool behaviour

The rules the tools keep, as a checklist for anyone adding or changing one. The bullets cite each other and the business rules and ADRs behind them, so they stay in this order. What LogSeq's data and API do underneath is in [logseq-behaviour.md](logseq-behaviour.md).

- [ ] Don't turn errors into empty results; propagate infrastructure errors: [BR-0003 (infrastructure-errors-propagate)](business-rules/0003-infrastructure-errors-propagate.md)
- [ ] Never cut results silently; any cap reports `ResultMeta`: [BR-0006 (no-silent-truncation)](business-rules/0006-no-silent-truncation.md)
- [ ] `get_current` without `includeChildren` (#655): LogSeq gives a block's children as unfetched tuples, which the tool drops, so a focused or selected block that has them carries `childrenTruncated: true` and no `children` key, at every depth. It is never read as a leaf: `get_block` fetches the children. The marker costs no extra call.
- [ ] Results are also bounded in characters (#485, ADR-0011): `explore_network`, `explore_timeline`, `explore_context` and `find_blocks` cut their main list from the tail, whole entries, until the text they send is at most `BUDGET_CHARS` (30,000, `src/budget.rs`), after the count caps. The cut is a `result_size_truncated` warning (`hasMore` true only where a call can read on, such as a date), costs no LogSeq call and leaves a result under the budget byte for byte as it was. A single entry over the budget comes back alone, never cut inside its text (BR-0007). There is no parameter to raise it. `find_blocks` (#506, #491) cuts in hits, measures both content blocks (tips included) and applies the budget in `call` only, so `find_blocks_with_meta` stays uncut; a size cut is a `result_size_truncated` warning and a `limit` cut a `results_truncated` one (ADR-0038: both lead `howToFetchAll` with the cursor, and `hasMore` is true exactly when `nextCursor` is there, in the meta block). A `limit` cut on the first page offers the raise of `limit` beside the cursor, measured at nothing: a raised result that is too large is cut again with a cursor of its own. The cursor's own length counts against the 30,000 characters (`src/paging.rs`, `page_of`). The other `get` and `find` tools (#507) apply it in `call` too, each in its own unit: `find_pages` in whole pages (#551: as `find_blocks`, both cuts lead `howToFetchAll` with the cursor, `hasMore` is true exactly when `nextCursor` is there, and a `limit` cut on the first page offers the raise of `limit` beside it; the `names` answers are the frame of page 1, never cut, and the pages after it leave them out (maintainer, #551); a page is never cut inside its names, so a first page over the budget comes back alone and the cursor moves past it); `get_page` with `detail` `full` and `get_block` with `include_children` in blocks in document order with `childrenTruncated` (`src/block_budget.rs`, `slice_blocks`), read to the end with `cursor` and `nextCursor` (ADR-0038, #552; `src/tree_paging.rs`): the entries are the blocks in document order, nested ones counted (for `get_block` the block is entry 0), a tree has no page size, only the budget, and a cut page is a `result_size_truncated` warning whose `howToFetchAll` says to pass the cursor. A page that starts inside a subtree lists its blocks at the top of `children`, each with `ancestors` (`[{ uuid, snippet }]`, outermost first, up to its parent below the frame; Markdown writes one `[under: A > B]` line before a run of them); a later page of a block is `{ uuid, continued: true, children }` (Markdown: `# Block ((uuid)) (continued)`), so a long block body is not repeated; a later page of a page repeats the page entity without `resolvedFrom` (how the name was read is said on the first page only); a warning the read made (`resolve_refs`) stays on every page, and `hasMore` stays true for one that offers a way of its own. `page` and `uuid` are optional in the schema and the handler refuses a call with neither the name nor a `cursor` (BR-0008). A tree is kept as a snapshot when its page leaves blocks behind and its JSON length times 13 (`resident_weight`) is within the 8 MiB a snapshot may weigh, so a page of about 630 KiB of JSON or more is built again for each page (page 1's 2 calls for `get_page`, 1 for `get_block`, up to 2 more with `resolve_refs`); `get_page` with `detail` `outline` in top-level blocks (200 full-length first lines are ~31,000 characters, so the cap of 200 alone does not hold it); `explore_context` (#493, #555) in entries, blocks first, then references, then related pages, each list read to the end with `cursor` and `nextCursor` (ADR-0038): the token holds the three lists' positions (`Position::Sections`) and the last block, reference and related page sent (`Anchor::Sections`), and `max_blocks`, `max_references` and `max_related_pages` are the page size of each list (0 leaves a list out and never makes a cursor). A page takes up to each page size from each position, then the budget cuts it from the tail (related pages, then references, then blocks); that cut is a `result_size_truncated` warning whose `howToFetchAll` says to pass the cursor, and a list's page size is a `blocks_truncated`, `references_truncated` or `related_pages_truncated` warning that leads with the cursor and offers the raise of its cap beside it on the first page, measured at nothing (a raised page that is too large is cut again with a cursor of its own); a count cap's warning for a list the size cut went into gives way to the size cut's. A list read to its end is empty on the pages after. `page` is optional in the schema and the handler refuses a call with neither the name nor a `cursor` (BR-0008). `resolvedFrom`, `resolvedAliases` and `summary` are said on the first page only (maintainer, #568), and the warnings the read made (an alias group cut, a part LogSeq did not answer) on every page; `resolve_refs` runs for the blocks and references a page takes, from LogSeq or from the snapshot; `explore_network` (#494, #556) in pages, in the order the walk admitted them, on the cursor (the walk runs to 500 pages and `max_nodes` is the page size; a page carries the edges whose later end it holds, so every edge is sent once; `truncated` is the walk's rules, and the `max_fanout` raise stays in `network_truncated`, unmeasured, and never makes `hasMore` true, which is the cursor's alone; the path with `to` has at most 4 pages and needs no cut); `explore_timeline` (#495, #554) in blocks, nested ones counted, the entries in order (days oldest first, newest first for `last_n` with no `page`, the blocks on non-journal pages last), with `max_blocks` as the page size: a page ends at `max_blocks` (`blocks_truncated`) or at the budget (`result_size_truncated`), and `nextCursor` reads on in either case, with no raise of `max_blocks` offered beside it (a page size of 0 offers the raise alone, and `hasMore` stays false); `get_current` in the selected blocks (the open page and the focused block are the frame); `check_links` in `refs.resolved` only (`ok`, the unresolved and ambiguous refs and `refsPreserved` are never cut: a gate does not drop a failure to fit a limit). `get_graph` has no list and is not cut. The library functions behind `call` (`find_pages`, `get_current`, `check_links`) make no cut. A new tool whose caps allow a result past the budget uses `budget::fit` too
- [ ] `find_blocks` (#491, #492) is one query for every combination of its filters: `text`, `page` (the blocks on a page), `links_to` (1 to 5 pages; a block matches when its `:block/refs` include a page from the alias group of each, so `[[x]]`, `#x` and `#[[x]]` count and plain text does not; `:block/path-refs`, refs inherited from ancestors, are not matched), `property` with `value` (a block property; the rules of `src/property.rs`) and a period (`start_date` with `end_date`, `last_n` or `preset`, exactly one, chosen by `src/period.rs`, which `explore_timeline` shares). At least one filter is required (`InvalidParameter` before any call; a blank page name is refused too), and an empty `text` is none. The pages are resolved by `require_page` before the query (`src/tools/find_blocks/scope.rs`): one resolver query per distinct name, in the order given, then one alias-group query for all of them, so a missing or ambiguous page is the first one's error and no search is made. The period requires `[?page :block/name]` so an app-made journal block that carries `:block/journal-day` is not matched as a page. Its `last_n` is the last N calendar days ending today, the same reading `explore_timeline` has (#525; it was `query_by_date_range`'s N most recent journals that exist, which takes a second call to learn, and every combination of `find_blocks` is 1) <!-- guard:history query_by_date_range -->. Results are one shape for every combination: LogSeq's pulled block with its page's `id`, `name` and `original-name` (slim: `pageName`), newest first by block id, the meta always in the second content block. `limit` is the page size and `cursor` reads on (ADR-0038, #550): a call with a `cursor` takes no other argument (the arguments are in the token, `last_n` and a preset as their start and end dates), and `totals.matches` counts every match of the list, the pages before this one included. A list that shrank below a cursor's position is an empty page that says `cursor_stale` (a cursor this server issued never points at the end of an unchanged list), with no miss tip, and `limit: 0` shows nothing, has no cursor (it would not move) and says so with a `results_truncated` warning that offers the raise alone, so its `hasMore` is false. The page notes (`resolvedFrom`, `resolvedAliases`) are said on the first page only. `tests/find_blocks_cursor_calls.rs` holds the calls: a hit costs none, a miss costs page 1's.
- [ ] `explore_timeline` (#495) is `query_by_date_range` and `get_concept_evolution` merged <!-- guard:history query_by_date_range get_concept_evolution -->. A period alone (`start_date` with `end_date`, `last_n` or `preset`, `src/period.rs`) is the journal pages in it and every block on them, one entry per day, empty days included, in 2 calls (`journals.rs`). A `page`, with or without a period, is the page's own blocks (`getPageBlocksTree`, the page's own entity as their `page`) and the blocks that link to it under any alias (one mentions query), one entry per journal day, oldest first, the blocks with no day (non-journal pages) last in an entry with `date: null` (`mentions.rs`); a period leaves those out, since they have no day in it (the maintainer's call on #495, one line in `days::in_period`). Both give one result, keys in BR-0013's order: `page`, `resolvedFrom`, `resolvedAliases`, `dateRange` (the period, or for a page with no period the span of its dated blocks), `hasMore`, `nextCursor`, `warnings`, `totals` (`{ blocks, days }`, with a cut), `summary` (`totalDays`, `totalBlocks`, `topConcepts`; the first page only) and `entries`. `last_n` is the last N calendar days ending today, in no call of its own (#525, as `find_blocks`), and lists newest first only with no page. `group_by` week or month joins consecutive days into one entry (`{ period, blocks }`, each slim block naming its page) after the cuts, so a cut never depends on it. `max_blocks` (default 200, max 1000, nested blocks counted) is the page size, and `max_entries` was folded into it. The blocks across the days are one list the cursor reads to the end (ADR-0038, #554): its place is an index, the anchor is the last block sent, a token stores a `last_n` or preset as `start_date` and `end_date` (and `newest_first: true` for `last_n` with no page, which dates can't say), and a day cut between two pages is on both with the same `date`, a block that starts a page under another naming it in `ancestors` (`slice_blocks`). `resolve_refs` runs over the page's blocks only, so the snapshot keeps the list as read, unresolved. The frame keys (`page`, `resolvedFrom`, `resolvedAliases`, `dateRange`) are on every page; `summary` and the tip are on the first only (the maintainer's call on #554). `summary.topConcepts` of a page counts what its mentions link (the mentions query pulls each ref as a page map, unless `top_concepts_limit` is 0; the page and its aliases, journal pages and the built-in task tags are left out), not the links inside the page's own blocks: the Editor API tree gives those refs as bare ids, and naming them takes one more LogSeq call, which would raise a ceiling and needs the maintainer's OK. `get_concept_evolution` had no `topConcepts`, so this is new, and a follow-up can add the call if the page's own links are wanted. The tool takes no aliases (BR-0008: `page` is optional here), and no `search_term`: text in a period is `find_blocks` with `text` and the same period
- [ ] `explore_network` (#666): its alias group is the pages within two `:block/alias` links of the page, in either direction (`alias_closure`, `src/resolve/queries.rs`, at most `MAX_ALIAS_SET_SIZE` pages). Two unrelated pages that both declare the same alias are two hops apart through the alias page, so one group holds them: `resolve` calls that name ambiguous, but the walk, its path search and the `links_to` scope of `find_blocks` merge the two pages and results can connect them. Kept as it is and written down, not changed (a different grouping is a contract change for the maintainer to decide). `dropped` in the `network_truncated` warning counts a page once, even when `max_fanout` cuts it at depth 1 and it is offered again at depth 2
- [ ] `null` from an API call is not `[]`: [BR-0011 (null-is-not-empty)](business-rules/0011-null-is-not-empty.md)
- [ ] `resolve_refs` is opt-in and non-lossy; one resolver, `resolve_block_refs`: [BR-0007 (resolve-refs-non-lossy)](business-rules/0007-resolve-refs-non-lossy.md)
- [ ] Guidance for the model (#44) lives outside the tools. Server `instructions` are in `src/instructions.rs`. Next-step tips: [BR-0009 (tips-are-advisory)](business-rules/0009-tips-are-advisory.md). Parameter aliases: [BR-0008 (param-aliases-best-effort)](business-rules/0008-param-aliases-best-effort.md). Every tool description needs a "Can't find" line ([ADR-0015 (tool-descriptions-state-limits)](adr/0015-tool-descriptions-state-limits.md)).
- [ ] Prompts and resources (#46) live in `src/prompts.rs` and `src/resources.rs`; `src/server.rs` only declares the capabilities and routes the requests. Both are read-only. A prompt returns one short user message naming the tools to call, defers to the `logseq-skills` workflow rather than copying it, quotes any argument it embeds, and rejects unknown or malformed arguments as `InvalidParams`. A test in `src/prompts.rs` checks that a prompt names only existing tools, so a tool rename fails it. `serverInfo.version` is the Cargo package version (`Cargo.toml`, read in `src/server.rs`), and `tests/rust-guards/version.test.ts` keeps it, `package.json` and `.claude-plugin/plugin.json` on the same version.
- [ ] Publishing (#46) is manual: a workflow that publishes runs only on `workflow_dispatch`, from `main`, and defaults to a dry run. Never publish, tag or release from a session. Why: [ADR-0017 (manual-npm-publish)](adr/0017-manual-npm-publish.md), carried over by [ADR-0035](adr/0035-native-binary-release-on-github-releases.md) (Decision 10). The npm workflow and packaging were the TypeScript server's and are gone; the rule stands for whatever replaces them.
- [ ] Slim output is the default: [BR-0012 (slim-output-default)](business-rules/0012-slim-output-default.md)
- [ ] Output format (#43). `get_page`, `get_block`, `explore_context` and `explore_network` (the network, and the path with `to`, through `render_path`) take `format: "json" | "markdown"` (default `json`, unchanged). Markdown is one plain text content block, not JSON-escaped, rendered by the one shared renderer in `src/markdown.rs` (`markdown_context.rs` for the context and network tools). `logseq://page/{name}` renders through the same `render_page`: never add a second renderer. Layout: page properties as `key:: value` (the page's pre-block text verbatim when the tree has one, so `[[refs]]` and hyphenated keys survive; only when there is no pre-block does `render_properties` rebuild them from the map: kebab-case keys, multi-value as `[[a]], [[b]]`; never rewrite a pre-block), blocks as tab-indented `- ` bullets, `((uuid))` refs untouched, `resolvedContent` on a `[resolved]` line under its block, related pages as `[[links]]`, references grouped by source page, and a footer after `---` for `warnings`, `hasMore` and tips (tips ride in the footer, not a second content block). Full Markdown omits block uuids on purpose (they bloat every bullet; `compact` adds them). An ambiguous name stays a structured JSON result in both formats; errors stay JSON `{error}`. `format` and `compact` are parsed at the boundary, like every tool argument (#60): parsed by `parse_args` (`src/args.rs`), with the `inputSchema` generated from the same argument type. Bad values are rejected with an `InvalidParameter` error. Markdown renders the full result, uncapped except the resource's `MAX_PAGE_CHARS`.
- [ ] TOON (#469, [BR-0014 (toon-output)](business-rules/0014-toon-output.md)). `find_pages` and `get_page` (with `detail: "outline"`) take `format: "json" | "toon"` (default `json`, byte for byte unchanged), a different type from the Markdown tools' (`ListFormat`, `src/output_format.rs`). `src/toon.rs` is the one encoder (the `toon-format` crate on the result `Value`, which keeps key order, `null`, `[]` and numbers). Every content block of the result, the tips block included, is written through `ListFormat::text`. An error and the ambiguous-name answer stay JSON. TOON writes a list as a table only when every row has the same primitive-valued keys, so it's smaller for these two lists and no smaller for `find_blocks` (rows with optional keys) or the `references` of `explore_context` (each row holds a whole block and its source page): don't add it to a tool without measuring the JSON and TOON result sizes against the fixture instance (`scripts/measure-output-size.ts` has no TOON section, so measure by hand). A `find_pages` result whose pages carry aliases is a list of objects, not a table, and saves little. Its `names` answers are a table only while every name has the same keys (`name` and `page`): one with `suggestions` or `candidates` makes the list objects.
- [ ] `compact` (#43) exists on `explore_context` only: block bodies become a first-line snippet (`src/snippet.rs`, 80 characters) plus the block's `((uuid))`; in JSON a block is `{ uuid, snippet }` and pages are `{ id, name, originalName }` (`src/compact.rs`). `summary`, `totals`, `warnings` and `hasMore` stay. It is off for `get_page` and `get_block` (`logseq_get_page` with `detail: "outline"` covers that), and for `explore_network`, which already carries no bodies. Compact skips `resolve_refs`, and `explore_context` says so with a `resolve_refs_ignored_in_compact` warning (resolving would put the bodies back and defeat compact; the warning names `compact: false` and `get_block` as the ways to get resolved text). For blocks shorter than the uuid, compact can be larger than the full markdown; it pays off on long blocks.
- [ ] `logseq_get_page` with `detail: "outline"` (#43, a tool of its own until #489): top-level `{ uuid, snippet, childCount }` (direct children only), in two calls. The query (`page_outline_blocks` in `src/tools/get_page/outline/queries.rs`) binds the resolved page id and returns the top-level blocks plus their direct children in one `or-join`; the tool counts children per parent in Rust and orders siblings by the `:block/left` chain. A page holds `MAX_OUTLINE_BLOCKS` (200) top-level blocks and the character budget, and a longer outline is read to the end with the cursor (ADR-0038, #553): `outline_truncated` (the count) or `result_size_truncated` (the budget) carries a `howToFetchAll` that says to pass `nextCursor`, the anchor is the uuid of the last block sent, and `totals.blocks` is every top-level block. The list is every top-level block (the 200 cap is applied per page, not at the query), kept as a snapshot, so a later page makes no call and a miss makes the same two. It is the step before `get_block` in the server `instructions`. `logseq_get_page` takes `page` and `detail` (`page`, the default, `full` for the page with its blocks, or `outline`), and a `format` or `resolve_refs` the `detail` cannot take is an `InvalidParameter` naming the valid ones (`check_combination` in `src/tools/get_page/mod.rs`): `outline` takes `json` or `toon` and no `resolve_refs`, `page` and `full` take `json` or `markdown`.
- [ ] Tool results are minified JSON (compact `serde_json` output, no layout whitespace). The parity test (`cargo test`) fails if any tool adds layout whitespace (a JSON result is compared by deep equality and then has to be minified, `tests/parity.rs` and `tests/parity_support/compare.rs`). `format: "markdown"` is the opt-in plain text exception (#43). Pretty output would need an opt-in parameter and an exemption there. Why: [ADR-0009 (minified-json-output)](adr/0009-minified-json-output.md).
- [ ] The config file is parsed once, by `load_config` in `src/config.rs` (#63), into a typed `Config`. Its failures are `ConfigError` variants; tell them apart by variant, never by message text. No config error message shows a config-file value or the file's text, since either can be the token ([ADR-0003 (no-secrets-in-source)](adr/0003-no-secrets-in-source.md)): a JSON parser's message sometimes quotes the file, and those are replaced. Only the `LOGSEQ_MCP_TIPS` error echoes its value, which holds no secret.
- [ ] Never write to stdout (`println!`, `print!`, `dbg!`, `io::stdout`). It's the MCP stdio channel; log with `eprintln!`. `tests/no_stdout.rs` fails on any hit in `src` (#82). Never log graph data either: [ADR-0004 (stderr-only-logging)](adr/0004-stderr-only-logging.md).
